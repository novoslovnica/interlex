# Duplicate service lexemes, variant-only candidates, canonical spellings — 2026-09-15/16

> Вынесено из AGENTS.md при реструктуризации 2026-09-26.

Three changes to how a token picks its lexeme, plus two batches of merges the maintainer confirmed word by word.

**Variant-only candidates are pruned** (`dbAnalyzer.matchForms`/`analyzeWord`, commit 6f6226c): a match now also carries `primary` — the form matched the token *as written*, is not a recognition `variant` and is not aorist/imperfect. If any lexeme matches primarily, lexemes reachable only through an expanded spelling (i→y, u→ų) or a variant form are dropped from the homonym pool; with no primary match the pool is unchanged. Lemma-level ambiguity fell sharply: tokens with 4+ competing lexemes 387 389 → 101 068, with 3 → 280 881, unambiguous 1 988 921 → 2 264 770.

**Adverbs and uninflected words take the canonical spelling from the stem** (`canonicalFromStem` in `lib/grammar/common/stem.ts`, used by `processUninflected` and `processAdverb`, commit f37c347). `Lexeme.value` is often undiacriticized ("treba", "velmi", "ze") while the stem carries the real spelling ("trěba", "veľmi", "že") — the same gap already fixed for verbs (`canonicalInfinitive`) and pronouns (`canonicalPronounLemma`), never for these classes. 344 uninflected lexemes were affected, some very frequent (ze/že 9 335 per mln, velmi/veľmi, dnes/dnėś). The plain value stays as a `variant: true` form so simplified spellings still find the word. Note ADV does **not** route through `processUninflected` (engine.ts dispatches it to `processAdverb`) — fixing one without the other silently does nothing for adverbs.

**Merges** (`2026-09-15-merge-service-duplicate-lexemes.ts`, `2026-09-16-merge-demonstratives-and-reflexives.ts`, `2026-09-16-merge-to-into-toj.ts`): 39 legacy lowercase-POS lexemes into 27 targets (ne, a, da, no, nu, kak/kako, tako, dobro, ty, ako, kogda, togda, ves, byti, ktory, ljudi, imati, treba, v/vȯ, mena, ja, li, žęti/žegti, lev), then ty-adj+toj-prep+to-PRON → tȯj-PRON, onoj → ony (POS → PRON, stem "ony"), sebe-PRON → se-PRON. Meanings are moved as separate rows, never collapsed — `lib/dedup/mergeLexemes.ts` is wrong for this, it folds every meaning into one and deletes the rest along with their ISV definitions. Data fixes in the same pass: `sej-PRON`'s irregular form `se` → `sje` (se/sę is the reflexive, sej the demonstrative — they are different pronouns, and the wrong row sent all 41 908 "se" tokens to the demonstrative, since an irregular form counts as a literal match and beats frequency); `se-PRON` gained se/sebe/sebě (sebę/sebě are inflections of sę); `voj-n`'s stem "vo" → "voj" (voj is the noun from "vyti"; the wrong stem made it decline as an o-stem from "vo" and swallow ~4 500 tokens of the preposition v/vo, which does not inflect at all).

**Four traps worth knowing, each cost a rerun:**
1. **Frequency is computed from corpus lemmas, i.e. from the winners.** A merge target that starts at 0 per mln loses every token to its competitor, and the next `compute-lexicon-frequency` run then *confirms* that loss. Merge scripts must carry the sources' frequency onto the target **before** reanalysis (`2026-09-16-carry-frequency-to-merge-targets.ts`), and a contaminated state is rolled back from a pre-merge backup (`2026-09-16-restore-frequencies-from-backup.ts`). Symptom seen live: "tak, tako-ADV" at 11.6 against taky at 5 120, so «tako» resolved to the adjective.
2. **Raw SQL does not move `Lexeme.updatedAt`**, and `corpus-refresh` selects work by `updatedAt > watermark` — the first refresh after a merge found 0 changed lexemes and did nothing. Set `updatedAt` explicitly in any script that edits lexemes outside Prisma.
3. **Never run a heavy `corpus.db` query while a reanalysis is writing.** A three-form `surfaceForm` scan (5M rows, unindexed) starved the writer into `SocketTimeout`, then `cannot start a transaction within a transaction`, killing a 3-hour run at document 37.
4. **`corpus-refresh` is only cheap when the affected share is small.** Five changed lexemes reached 55 spellings → 86 900 sentences (32% of the corpus) and took 2h12m at 0.10 doc/s, against 0.55 doc/s for a full pass; the script prints this warning itself. Reanalyzing a hand-picked document list (documents still holding the wrong slug) is the cheaper middle ground.

**Measured after all of it**: green 1 090 041 (26.5%), ambiguous 2 501 052 (60.7%), yellow 66 602 (1.6%), red 459 746 (11.2%). Green fell and ambiguous rose against the pre-fix run (1 164 464 / 2 426 642) — expected: an adverb now generates both the canonical and the plain spelling, so a token that matched one lexeme matches two, while the winner became correct. Spot checks: vo → v/vȯ-ADP (all 4 433), se → se-PRON (41 908), to → tȯj-PRON (53 627), tom → tȯj-PRON 3 716 / tom-NOUN 879 (both readings are real), trěba → treba-ADV, imaje → "imeti, imati-VERB".

**Still open**: `CorpusTokenCandidate` rows in documents not reanalyzed since the merges still name deleted slugs (harmless, the winning `CorpusToken` is correct; the next full pass rewrites them); `voj-n` catches the name Vojta/Vojty/Vojto (102 tokens); 529 more legacy lowercase-POS lexemes have a same-spelling twin of the new format (98 of them above 100 per mln) and have not been reviewed.
