# Ограниченная пагинация API лексикона — 2026-10-18

## Контракт

`GET /api/lexicon` и `GET /api/lexicon/reverse` принимают:

- `offset`: целое неотрицательное число в безопасном диапазоне JS; по умолчанию 0.
- `limit`: целое от 1 до 100; по умолчанию 50.

Пустые, дробные, отрицательные, повторённые и нечисловые параметры, а также
слишком большой limit дают HTTP 400 до обращения к auth/БД. Проверка повторяется
в сервисах для прямых вызовов. LIMIT/OFFSET передаются SQL-параметрами.

Формат ответа сохранён: массив строк. Единица страницы — **лексема + значение**,
а не лексема: одна лексема с множеством значений больше не разворачивается в
неограниченный массив после LIMIT. Лексема без значений занимает одну строку
с meaningId=null. Полный порядок: Lexeme.id ASC, Meaning.id ASC.

Следующий offset = предыдущий offset + число полученных строк. Короткая/пустая
страница завершает выдачу. У полной последней страницы допустим ещё один запрос,
возвращающий пустой массив. Как и у обычной offset-пагинации, стабильность между
запросами предполагает отсутствие параллельных изменений набора результатов.

## Выборка

Раньше прямой поиск получал все совпавшие id без LIMIT. Листинг ограничивал
лексемы, затем разворачивал значения и удалял уже выбранные строки по фильтрам
проверки — это превышало размер страницы и создавало преждевременные пустые
страницы. Теперь поиск, категории, тип употребления и фильтры проверки применяются
в SQL до пагинации. Обратный поиск использует ту же ограниченную выборку строк,
сохраняя показ всех значений лексемы, совпавшей по переводу.

Сохранены CORE-аллофоны, FTS5/trigram, LIKE для коротких запросов и объединение
этимологического/упрощённого ввода через foldDiacritics. Совпадения не дублируются
по каналам поиска. LIKE экранирует также обратный слеш, `%` и `_`.

Обогащение переводами/аллофонами выполняется только для выбранной страницы в
одной читающей транзакции. Соединение закрывается при успехе, пустом результате
и ошибке. Область видимости скрытых слов осталась прежней: ADMIN/MODERATOR.

## Интерфейсы

Админская таблица теперь загружает следующие страницы и при непустом поисковом
запросе. Публичный словарь запрашивает страницы по 20 строк; «Загрузить ещё»
получает следующую страницу вместо раскрытия ранее загруженного полного массива.
Параметры активного поиска сохраняются для дозагрузки, устаревшие ответы
игнорируются, ошибки отображаются. Ключ карточки включает meaningId.

## Проверки

Тесты HTTP-границы проверяют валидацию до auth/БД, значения по умолчанию, формат
массива и видимость скрытых слов. Интеграционные тесты SQLite :memory: с настоящими
FTS5-таблицами проверяют листинг, короткий/FTS/обратный поиск, границы внутри
многозначной лексемы, фактический максимум 100 строк, фильтры до LIMIT, аллофоны,
диакритику, последние страницы и закрытие соединений. Дополнительно проверено
чтение соседних страниц на локальной interlex.db.

Изменений схемы и данных нет; миграция не нужна.
