# Дистрибутивный анализ морфем. Словарный пилот 25 ноября 2026

В локальном снимке Interlex связи с корнем есть у 4 477 из 21 278 публичных лексем (21,0%), с суффиксом — у 110 (0,52%), с приставкой — у 0. Два наиболее представленных суффикса, `-ec` и `-ak`, дают 107 из 110 лексем с суффиксами. Текущая разметка позволяет выбрать материал для ручной сверки и выделить первые словообразовательные пары для №75. Доли характеризуют покрытие разметкой в словаре.

[Редакторский пилот](morpheme-editorial-pilot-2026-11-25.md) продолжает этот проход. В нём проверен инвентарь 13 аффиксов, собраны совпадения и выделена первая пачка привязок и исправлений корней.

## Выборка и единица подсчёта

Использован локальный `interlex.db` от 25.11.2026 (SHA-256 `566d3b6ad41e8b926104dd7a9e8ed8945faaa7e9b3156bcef79f1cef5b3a4ece`, журнал WAL на момент хеширования пуст). Подсчёт выполнен в режиме чтения для `Lexeme.isPublic = 1`. Тип определяется по `Morpheme.type`, принадлежность к семье — по идентификатору морфемы. Повторные связи одной лексемы с одной морфемой сведены к одной паре. В публичной части найдено 299 таких пар с повторами. Отдельные записи с одинаковым написанием считаются по разным `Lexeme.id`. Варианты `MorphemeAllophone` показаны как формы исходной морфемы.

## Сочетаемость аффиксов

Число корней в таблице — количество разных идентификаторов корня, связанных с теми же лексемами, что и суффикс. Производящую основу и её часть речи можно установить при сверке конкретной пары.

| Суффикс | CORE | Публичных лексем | Части речи в карточках | Лексем с корнем | Разных корней |
| --- | --- | ---: | --- | ---: | ---: |
| `-ec` №1720 | `ec` | 83 | 80 сущ., 1 прил., 2 гл. | 82 | 74 |
| `-ak` №1716 | `ak` | 24 | 19 сущ., 2 прил., 3 нареч. | 24 | 19 |
| `-ov-` №1730 | — | 1 | 1 прил. | 0 | 0 |
| `-ev-` №1731 | — | 1 | 1 прил. | 0 | 0 |
| `-sk-` №1732 | — | 1 | 1 прил. | 0 | 0 |

- Для `-ec` справочник даёт две разные входные части речи с существительным на выходе. Основа прилагательного `glup-` №7807 сочетается с `-ec` у `glupec` №771. Производное с тем же написанием №7803 и пример от названия страны `Albanija` №4704 → `Albanec` №4703 есть в снимке без суффиксальной связи. Сверенные примеры показывают, что сохранённые связи пропускают часть засвидетельствованных сочетаний. [Суффиксы существительных](https://interslavic.fun/learn/vocabulary/word-formation/#suffixes)
- Для `-ak` сверена именная основа `ryb-`. Пара `glupy` №7807 → `glupak` №769 со значением «глупец» даёт кандидата на основу прилагательного. В карточках уже есть общий корень №363 и связь производного с `-ak`. У `brak` №5720 и `inako` №8520 сохранённый корень целиком включает буквы `ak`. Для этих двух лексем границы требуют проверки до учёта в распределении по производящим основам. [Примеры образования существительных с `-ak`](https://interslavic.fun/standard/morphology/derivation/)
- `vlastenec` №3840 с переводом «патриот» записан как `VERB`. `zverolecba` №4353 «ветеринария» несёт связь с `-ec`, хотя её словарная основа `zvěrolěčb` требует отдельного разбора. Эти две карточки подходят для очереди сверки частей речи и границ.
- В отчёте качества №113 уже есть кандидаты на `-ov-`, `-ev-`, `-sk-`. В аудите есть по одной связи для каждого из трёх суффиксов у слов `domovy` №6836, `aluminijevy` №4755 и `slovjansky` №18512. Для распределения по основам нужны проверенные производящие пары. [Отчёт качества словаря](../app/admin/dashboard/lexicon-quality/page.tsx)

## Условия расширения пилота

`LexemeMorpheme` хранит принадлежность морфемы лексеме. Позиция и границы отсутствуют. Поэтому порядок и границы в пилоте установлены вручную для пяти примеров. Для следующей выборки редактору нужны исходная форма, производящая лексема, границы в выбранном написании и ссылка на основание разбора. Первые случаи для сверки — разделение `dom`, полная граница `knig/kniž`, вторая основа у сложных слов и спорные привязки `-ec` и `-ak`.

Корпусный этап начинается после проверки привязок токенов к лексемам этих семей. Его знаменатели — число проверенных словесных токенов в выборке и число документов, из которых они взяты. Покрытие морфемной разметкой и долю неоднозначных привязок следует показать рядом с частотами и соседними леммами. Синтаксические контексты требуют проверенной разметки зависимостей.

## Воспроизведение подсчётов

Из корня репозитория откройте `sqlite3 -readonly interlex.db` и выполните запросы ниже. Запросы используют один снимок в рамках транзакции.

```sql
BEGIN;

WITH links AS (
    SELECT DISTINCT l.id AS lexeme_id, m.type
    FROM lexemes AS l
    JOIN lexemes_morphemes AS lm ON lm.lexemeId = l.id
    JOIN morphemes AS m ON m.id = lm.morphemeId
    WHERE l.isPublic = 1
)
SELECT (SELECT count(*) FROM lexemes WHERE isPublic = 1) AS public_lexemes,
       count(DISTINCT CASE WHEN type = 0 THEN lexeme_id END) AS with_root,
       count(DISTINCT CASE WHEN type = 1 THEN lexeme_id END) AS with_prefix,
       count(DISTINCT CASE WHEN type = 2 THEN lexeme_id END) AS with_suffix
FROM links;

WITH links AS (
    SELECT DISTINCT l.id AS lexeme_id, l.pos, m.id AS morpheme_id, m.type
    FROM lexemes AS l
    JOIN lexemes_morphemes AS lm ON lm.lexemeId = l.id
    JOIN morphemes AS m ON m.id = lm.morphemeId
    WHERE l.isPublic = 1
)
SELECT m.id, m.value, f.code, a.value AS variant, member.pos,
       count(DISTINCT member.lexeme_id) AS lexemes,
       count(DISTINCT root.lexeme_id) AS lexemes_with_root,
       count(DISTINCT root.morpheme_id) AS distinct_roots
FROM morphemes AS m
LEFT JOIN morpheme_allophones AS a ON a.morphemeId = m.id
LEFT JOIN allophone_flavors AS f ON f.id = a.flavorId
LEFT JOIN links AS member ON member.morpheme_id = m.id
LEFT JOIN links AS root ON root.lexeme_id = member.lexeme_id AND root.type = 0
WHERE m.id IN (73, 127, 258, 481, 585, 1237, 1571)
   OR m.type = 2 AND member.lexeme_id IS NOT NULL
GROUP BY m.id, m.value, f.code, a.value, member.pos
ORDER BY m.id, f.code, member.pos;

COMMIT;
```

Последний запрос показывает распределение по частям речи и вариантам. Если у морфемы несколько вариантов, используйте строки одного варианта для подсчёта лексем. Число разных корней у суффикса по всем частям речи пересчитывается тем же запросом с удалением `member.pos` из `SELECT`, `GROUP BY` и `ORDER BY`.
