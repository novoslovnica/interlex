# Оценка проекта и предложения в роадмап (2026-09-19)

## О документе

Мейнтейнер попросил оценить проект: какие есть минусы/ошибки и что добавить в роадмап. `docs/roadmap.md` уже большой (98 пунктов) и хорошо покрывает фичи и лингвистический долг — поэтому оценка сосредоточена на том, чего в нём **нет**. Всё ниже проверено по коду/файлам 2026-09-19, а не взято из документации. Пункты 99–113 — предложения, в `docs/roadmap.md` пока не перенесены; ничего из этого не реализовано.

## Что хорошо (коротко)

- Дисциплина «не фабриковать лингвистический факт», reimport-safety через `source`, решения по корпусной частотности — сильная сторона проекта.
- CI с ratchet-гейтами реально работает: baseline lint 214→79, tsc 116→56; 41 тест-файл; из 75 API-роутов единственный мутирующий без проверки — осознанно публичный `/api/synonyms/second-level`.
- `dangerouslySetInnerHTML` только для JSON-LD, Markdown идёт через `ReactMarkdown` — XSS-поверхность маленькая.

## Найденные минусы (нет в роадмапе)

### 1. Деплой — самое слабое место проекта
- `rebuild-remote.sh`: `rm package-lock.json` + `npm i` на проде — сборка невоспроизводима, прод может получить не те версии, что прошли CI (при `next-auth` beta и Prisma 7 это реальный риск). Нужно `npm ci`.
- `rm -rf .next` перед `npm run build` под работающим `next start` — сайт сломан на всё время сборки; упавшая сборка = сайт лежит, отката нет.
- `release.sh`: `sshpass` с паролем из `.env.release` вместо SSH-ключа; `.env` копируется scp при каждом релизе.
- Версии Node расходятся: CI — 22, прод (`interslavic-lexicon.service`) — v20.20.2; нет `.nvmrc`/`engines`. Важно для нативного `better-sqlite3`.
- Нет реестра применённых `scripts/db/*.ts`: ~60 миграций, какие применены на проде — известно только из памяти. Нужна таблица `_applied_scripts` + раннер «применить недостающие».

### 2. Бэкапы
- В корне ~25 ГБ `*.backup-before-*` (corpus — 3 штуки по 0.6–4.8 ГБ, interlex — 7 по 200 МБ), все на том же диске, что и оригинал. Это страховка от плохой миграции, но не от потери диска/сервера.
- Нет автоматического offsite-бэкапа прода (в скриптах деплоя нет ни cron, ни rsync). `auth.db` с реальными пользователями и ручные правки модераторов невосстановимы.
- Нет политики ротации: бэкапы копятся бессрочно.

### 3. SEO — упущенная аудитория
- Нет `sitemap.xml`, `robots.txt`, `manifest`, OG-картинок (проверено `find app public`). Для словаря на 24 тыс. страниц слов + библиотека + праслав. словарь sitemap — самый дешёвый способ вырасти в поиске. `generateMetadata` и JSON-LD уже есть — не хватает только индексации.
- Нет `hreflang`/альтернатив по локалям (локаль в cookie, URL один) — поисковик видит только одну языковую версию.

### 4. Устойчивость UI
- Ни одного `error.tsx` / `not-found.tsx` / `loading.tsx` во всём `app/` — любая ошибка серверного компонента даёт дефолтный экран Next, 404 не локализован.
- 93 `console.*` в `app/lib/components` без структурного логгера (усугубляет п.23 роадмапа про observability).

### 5. Безопасность (мелкое)
- `next.config.ts`: нет security-заголовков (CSP, `X-Frame-Options`, `Referrer-Policy`, HSTS).
- `serverActions.bodySizeLimit: "50mb"` глобально — нужно только загрузке библиотеки, а действует на все server actions (включая публичные).
- `getClientKey` доверяет первому элементу `x-forwarded-for` — клиент может подделать заголовок и обойти rate limit, если nginx не перезаписывает его. Проверить конфиг nginx, брать последний доверенный hop или `x-real-ip`.
- `ignoreBuildErrors: true` всё ещё включён (уже в п.25, но это главный оставшийся риск типов).

### 6. Гигиена репозитория и документации
- `CLAUDE.md` устарел: пишет «vitest not set up», «N+1 on /words/[id]» — оба закрыты 2026-08-12. AGENTS.md (552 строки) превратился в журнал инцидентов; реальные правила тонут. Предложение: хроники → `docs/history/`, в AGENTS.md оставить только действующие правила и ловушки.
- `prisma/generated` (94 файла) закоммичен, хотя CI генерирует его сам — лишние диффы и риск рассинхрона.
- `data/essja_dump.json` (46 МБ) в git; `.claude/worktrees` — 60 МБ мёртвого дерева с тестами, которые находит `find`.
- Файлы-гиганты: `ArticleForm.tsx` 1525 строк, `roots-client.tsx` 1052, `processors.ts` 1037.

### 7. Архитектурные риски на горизонте
- `corpus.db` — 4.9 ГБ, 60% токенов омонимичны (2.5 млн), полный reanalyze — часы, частотность зависит от победителей (ловушка №1 из AGENTS.md). Нет **эталонной размеченной выборки**: каждое изменение движка оценивается по «сколько кластеров распозналось», а не по точности. Регрессия вроде `voj-n`/`sej-PRON` ловится только глазами.
- In-memory кэши (rate limiter, rhyme, VerbGovernment, analyzer singleton) — всё завязано на один процесс; сейчас нормально, но стоит явно зафиксировать как ограничение.
- Тесты грамматического движка — 762 строки на ~10 тыс. строк движка, `declineNoun` — снапшоты без лингвистической проверки.

## Предложения в роадмап (новые пункты, нумерация с 99)

**P1 — надёжность**
- 99. Воспроизводимый деплой: `npm ci`, сборка в отдельный каталог + атомарное переключение (symlink) + откат, SSH-ключ вместо `sshpass`, единая версия Node (`.nvmrc` + `engines`, выровнять CI и прод).
- 100. Реестр миграций: таблица `_applied_scripts` в каждой БД + `npm run db:apply-pending`.
- 101. Offsite-бэкапы прода (ночной `sqlite3 .backup`/`VACUUM INTO` → внешнее хранилище, ротация 7/4/12) + уборка локальных `backup-before-*` старше N недель. Проверка восстановления раз в квартал.
- 102. Security-заголовки + сузить `bodySizeLimit` + проверить доверие к `x-forwarded-for`.

**P2 — качество**
- 103. `error.tsx`/`not-found.tsx`/`loading.tsx` (локализованные) на корне и ключевых сегментах.
- 104. **Золотой корпус**: 300–500 вручную размеченных предложений (лемма+POS+падеж) → скрипт метрик точности/полноты дизамбигуации, запускаемый перед каждым изменением движка. Превращает «проверил на глаз» в число; заодно основа для п.70 (UD-treebank).
- 105. Реструктуризация документации (AGENTS.md → правила; история → `docs/history/`; обновить CLAUDE.md).
- 106. Убрать `prisma/generated` из git, большие дампы — в git-lfs или release-артефакт; удалить `.claude/worktrees`.
- 107. Разбить `ArticleForm.tsx`/`roots-client.tsx`/`processors.ts` попутно с разбором `any`.

**P3, уровень A — рост аудитории**
- 108. `sitemap.xml` (слова, библиотека, праслав., учебник; с разбивкой на индексные файлы), `robots.txt`, OG-изображения для страницы слова (слово латиницей+кириллицей, генерация через `next/og`).
- 109. Локаль в URL (`/ru/...`, `/en/...`) + `hreflang` — вместе с п.108 даёт индексацию всех трёх языковых версий. Крупнее по объёму, можно после 108.
- 110. «Слово дня» (главная + RSS п.64 + Telegram-канал через уже существующую Telegram-интеграцию) — дешёвый повод возвращаться, выбор по `corpusFrequencyPerMln` + наличию проверенных переводов.

**P3, уровень B — использование уже собранных данных**
- 111. Активное обучение для очереди омонимов: сортировать 2.5 млн неоднозначных токенов не по порядку, а по «одно решение модератора закрывает N токенов» (одинаковая форма + одинаковый набор кандидатов), с массовым применением решения. Сейчас `TokenSidebar` решает по одному токену — при таком объёме очередь неисчерпаема.
- 112. Статистическая дизамбигуация поверх правил: когда п.104 и ручные решения дадут обучающую выборку — простой n-граммный/HMM-теггер по POS+падежу как ещё один слагаемый `scoreMatch`. Без выдумывания фактов: учится только на подтверждённых разборах.
- 113. Отчёт о качестве словаря для модераторов: лексемы без значений (3 079), без POS (212), расхождение `value`/`stem`, дубли-кандидаты — одной страницей на `/admin/dashboard` вместо разовых скриптов (данные уже посчитаны в разделе «Ещё не сделано» docs/history/2026-09-16-digraph-dz-merges.md).

## Рекомендуемый порядок

99 → 101 → 100 (защита данных и деплоя, 1–2 дня суммарно) → 108 (полдня, максимальный внешний эффект) → 103 → 104 (открывает 111/112 и снимает главный методологический риск корпусной работы).

## Как перепроверить факты

- Каждый факт из раздела «минусы» воспроизводим командами: `cat rebuild-remote.sh`, `ls -la *.backup-*`, `find app public -iname "*sitemap*"`, `find app -name error.tsx`, `cat next.config.ts`, `git ls-files prisma/generated | wc -l`.
