## P5 — стратегические направления (другой масштаб и характер задачи, не однодневные фичи)

67. ⬜ **RFC/голосование сообщества за новые слова и грамматические правила** — сейчас решения о языковом стандарте принимает модератор кулуарно; формальный процесс предложений с обсуждением и голосованием — это смена модели управления языком, а не техническая фича, обсуждать масштаб и права доступа отдельно.
68. ⬜ **Разговорник для практической/экстренной коммуникации** — исторический смысл ISV был именно в этом (взаимопонятная межславянская коммуникация в реальных ситуациях: турист, экстренные службы), но сам текст фраз сгенерировать нельзя (тот же принцип "не фабриковать лингвистический факт", что и у `VerbGovernment`/окончаний) — нужен человеческий перевод, в идеале от уже проверенного многоязычного гуманитарного разговорника (такие делают NGO/Красный Крест для кризисной коммуникации), а не с нуля. Что реально автоматизируется: (1) **слот-шаблоны + грамматический движок** — фразы вида "Boli me [часть тела]" пишутся один раз как шаблон, конкретные существительные подставляются и склоняются через `lib/grammar/` автоматически (единственное место, где движок реально *генерирует* контент фразника, а не просто отображает готовое); (2) **схема данных** — `PhrasebookPhrase`+переводы можно смоделировать по образцу `Meaning`/`Translation` (тот же `verified`-флаг, та же очередь модерации по типу `/admin/translation-cards`); (3) **аудио** — если делать TTS через espeak-ng (п.33), для коротких фраз это ещё дешевле и даже важнее, чем для отдельных слов; (4) **офлайн-UI по сценариям** (мед./полиция/транспорт/ночлег) — напрямую использует PWA/офлайн-режим (п.47), т.к. разговорник без сети в реальной ситуации — весь смысл фичи.
69. ⬜ **Грамматический движок как отдельная npm-библиотека** — `lib/grammar/` уже самодостаточный модуль; вынесенный отдельно, он мог бы использоваться другими славянскими NLP/conlang-проектами, не только этим сайтом.
70. ⬜ **UD-treebank для лингвистов-исследователей** — в проекте уже считается полноценный Universal Dependencies разбор корпуса (`CorpusDependency`, см. AGENTS.md "Corpus Syntax Parser"); оформленный как публикуемый treebank в стандартном формате — готовый вклад в академическое NLP-сообщество, не только внутренний движок сайта.
71. ⬜ **Linked Open Data / интеграция с Wikidata** — опубликовать лексикон как структурированные связанные данные, чтобы сайт стал канонической ссылкой, на которую опираются другие ресурсы (Wiktionary и т.п.), а не только конечной точкой для людей.
72. ⬜ **Полноценный MT-движок связного текста** (не пословный перевод, как сейчас `/translate`) — можно было бы обучать/дорабатывать на уже собираемом параллельном корпусе.
73. ⬜ **AI-собеседник для разговорной практики** — чат-бот, "говорящий" на ISV, для практики речи, а не только чтения/письма.
