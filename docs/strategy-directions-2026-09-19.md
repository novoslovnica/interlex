# Глобальные направления развития (2026-09-19)

## О документе

Продолжение `docs/roadmap-review-2026-09-19.md`. Там — технический долг и точечные пункты; здесь — крупные направления, куда проект может расти **помимо работы с текстами/корпусом**. Это предложения для обсуждения, ничего из этого не реализовано и в `docs/roadmap.md` не перенесено. Направления, уже записанные в P5 роадмапа (RFC-голосование, разговорник, движок как npm-библиотека, UD-treebank, Wikidata/LOD, MT, AI-собеседник), здесь не повторяются — только то, чего там нет, либо то, что меняет их приоритет.

Исходная мысль: у проекта накоплены четыре актива, которых нет ни у одного другого ISV-ресурса, и сейчас каждый используется на малую долю возможного:

| Актив | Что есть сейчас | Как используется |
|---|---|---|
| Грамматический движок (`lib/grammar/`) | полные парадигмы, акцентология, распознавание форм | таблицы на странице слова, разметка корпуса |
| Многоязычная матрица | 24 тыс. лексем × 18 языков (~430 тыс. переводов), праслав. словарь, `intelligibility` | строки переводов на странице слова, пословный `/translate` |
| Семантическая сеть | 56 тыс. `semantic_relations`, синсеты RuWordNet с ILI, 64 NSM-примитива, `CoreVocabularyConcept` | список синонимов + граф на странице слова |
| Пользователи и API | OAuth, SRS-карточки, публичный API v1 с ключами | карточки, 7 read-only эндпоинтов |

Каждое направление ниже — это «достроить продукт поверх одного из активов».

## Направление 1. Из словаря — в учебную платформу

**Почему.** Самый большой разрыв между заявленным и сделанным: «Учебник» в описании проекта — это одна страница (`app/textbook/ru/`, только русский). При этом всё, из чего делается курс, уже есть: CEFR-уровни лексем, частотность, SRS, readability библиотеки, движок, способный *проверять* ответы.

**Что строить.**
- **Курс как данные, а не как страницы**: модель `Lesson → Exercise` (в `library.db` или отдельной `course.db`), упражнения — типизированные (выбор формы, подстановка, перевод, порядок слов), ответы проверяет грамматический движок, а не захардкоженный ключ. Один урок пишется один раз и работает для всех слов подходящего класса.
- **Курс от родного языка.** Главное преимущество ISV — носитель славянского языка уже понимает 70–80%. Курс для поляка и для болгарина должен быть разным: что уже знакомо — пропустить, что ложный друг — подсветить, какие звуковые соответствия выучить первыми. Данные для этого есть (переводы на 18 языков + праслав. этимоны); это объединяет пп. 74, 79, 91 роадмапа в один продукт.
- **Адаптивная модель знаний ученика**: не только SM-2 по словам, а оценка владения *грамматическими категориями* (творительный мн. ч. даётся хуже, чем родительный ед. ч.) — упражнения подбираются под слабые места.
- **Сертификация уровня**: placement-тест (п.59) + итоговый тест по уровню → публичная страница-сертификат. Для сообщества конланга это значимый социальный объект.

**Первый шаг.** Схема `Lesson/Exercise` + один тип упражнения («поставь в падеж») с проверкой через `declineWordAutomatically`, 5 уроков A1 для русскоязычных. Это же закрывает п.40 роадмапа.

## Направление 2. Сравнительно-славянская платформа (не только ISV)

**Почему.** Матрица «понятие × 18 славянских языков + праславянская форма» ценна сама по себе, независимо от ISV. Аудитория славистов, студентов-филологов и просто любопытных носителей в десятки раз больше аудитории ISV — и она приходит на сайт, попутно знакомясь с ISV.

**Что строить.**
- **Страница понятия** (а не слова): одно значение → формы во всех языках в ряд, сгруппированные по когнатным гнёздам, с праслав. этимоном; карта распространения корня (какой корень в каких языках победил). Развитие п.52.
- **Регулярные звуковые соответствия, выведенные из данных**: выравнивание когнатов по праслав. форме даёт таблицы рефлексов (\*tort → рус. -оро-, пол. -ro-, чеш. -ra-) с примерами и исключениями — автоматически, с ручной верификацией. Это и учебный материал (п.79), и научный результат.
- **Калькулятор взаимопонятности**: вставил текст на любом славянском языке → какая доля лексики понятна носителю другого языка; та же метрика для ISV-текста по всем языкам сразу («этот текст поймут 83% поляков, 61% болгар»). Прямой инструмент для авторов ISV-текстов и аргумент для самого языка.
- **Объективная оценка кандидатов в слова**: при предложении нового слова автоматически считать покрытие по языкам/населению — формализует то, что сейчас решается экспертно. Основа для RFC-процесса (п.67): голосование получает числа, а не только мнения.

**Ограничение.** Качество переводов неравномерно (en — 56 тыс., mk — 2,5 тыс.; многие языки ровно по 19 054 — похоже на машинную заливку, `verified` мало). Поэтому направление упирается в **краудсорсинг верификации** (см. направление 5) — их стоит вести парой.

**Первый шаг.** Страница понятия для `CoreVocabularyConcept` (малое, уже курируемое множество) + публичный дашборд полноты (п.76).

## Направление 3. Настоящий переводчик

**Почему.** `/translate` пословный. Полноценный MT записан в P5 как «обучать нейросеть» — это дорого и параллельного корпуса мало. Но есть дешёвый промежуточный путь, уникальный для этого проекта: **rule-based перевод между близкородственными языками** (подход Apertium) работает хорошо именно для славянских пар, и два самых дорогих его компонента уже сделаны — морфологический анализатор (`DbAnalyzer`) и генератор (`lib/grammar/`), плюс двуязычный словарь.

**Что строить.**
- **ISV → славянский язык, уровень «глосса с грамматикой»**: анализ ISV-формы → лемма + граммемы → перевод леммы → показать граммемы. Не генерирует целевую форму (движка для русского/польского нет), но уже на порядок полезнее пословного.
- **Славянский язык → ISV с генерацией формы**: внешний морф-анализ исходного языка (pymorphy для ru/uk, Morfeusz для pl, UDPipe для остальных) → перенос граммем → `lib/grammar/` порождает правильную ISV-форму. Здесь движок работает на полную.
- **Гибрид с LLM**: LLM делает черновой перевод, а движок и словарь *валидируют* — каждое слово должно распознаваться `DbAnalyzer`, нераспознанное подсвечивается или заменяется словарным. Это решает главную проблему LLM в ISV — выдуманные слова и формы — и не требует обучения модели.
- **Проверка ISV-текста** (п.55) — тот же конвейер без этапа перевода; естественный побочный продукт.

**Первый шаг.** Режим «глосса с грамматикой» на `/translate` для ISV→ru: всё нужное уже в репозитории.

## Направление 4. Семантическая сеть как продукт

**Почему.** 56 тыс. связей и синсеты с ILI — это зачаток **Interslavic WordNet**, но наружу виден только список синонимов. `prime_exponents` пуст (0 строк) — NSM-слой заведён и не начат.

**Что строить.**
- **Тезаурус-навигатор**: вход не по слову, а по смыслу — дерево гиперонимов, тематические поля, «слова рядом по смыслу». Закрывает п.81, но на реальной таксономии, а не на плоском `mainCategory`.
- **Публикация как Open Multilingual Wordnet-совместимого ресурса**: через ILI сеть автоматически стыкуется с wordnet'ами всех языков. Это академическая видимость дешевле, чем treebank (п.70), потому что данные уже в нужной форме.
- **Поиск по смыслу** (п.20): эмбеддинги значений (многоязычная модель по определениям + переводам) → «найди слово, которое значит…», похожие слова, автоподсказка кандидатов в синонимы модератору. Хранить векторы можно в SQLite (`sqlite-vec`), не меняя стек.
- **Обнаружение лексических лакун**: понятия, которые есть в базовых списках/wordnet, но для которых в ISV нет слова → очередь для словотворчества, с автоматически подобранными славянскими когнатами как кандидатами. Превращает развитие словаря из реактивного (что встретилось) в планомерное.
- **Толковый словарь на ограниченном словаре**: определения ISV-слов, написанные только через `CoreVocabulary`/примитивы — как у Longman Defining Vocabulary. Делает словарь самодостаточным (ISV→ISV), а не только переводным. Это контентная работа, но инструмент контроля («в определении есть слово вне ядра») — простой.

**Первый шаг.** Заполнить `PrimeExponent` для 64 примитивов (это день работы лингвиста, UI уже есть на `/admin/primes`) и выпустить страницу гиперонимного дерева.

## Направление 5. Сообщество и модель участия

**Почему.** Сейчас всё держится на одном мейнтейнере и нескольких модераторах, а очереди огромны (2,5 млн омонимов, 75 тыс. кластеров кандидатов, сотни тысяч непроверенных переводов). Кодом это не решается — только людьми.

**Что строить.**
- **Микрозадачи для любого залогиненного пользователя**: «верен ли этот перевод на ваш родной язык?» (да/нет/не знаю) — по образцу `/admin/translation-cards`, но публично, с согласованием нескольких ответов вместо доверия одному. Носителей 18 языков модераторами не наберёшь, а как волонтёров на 2 минуты в день — можно.
- **Репутация и роли от вклада**: точность ответов относительно консенсуса → вес голоса → автоматическое предложение роли модератора. RBAC для этого уже гибкий (`FeaturePermission`).
- **Профиль участника и публичная статистика вклада** — основная мотивация в волонтёрских лингвопроектах (Tatoeba, Wiktionary).
- **Страница обсуждения у слова** — сейчас обратная связь только через одноразовый `ContentReport`; для спорных слов нужна нить обсуждения, она же — техническая основа RFC (п.67).
- **Прозрачность решений**: публичная история изменений (п.61) + обоснование у спорных решений. Для языка-стандарта доверие к процессу важнее скорости.

**Первый шаг.** Публичные карточки верификации перевода для языка из `UserSettings` пользователя, с порогом согласия 3 ответа.

## Направление 6. ISV там, где люди уже находятся

**Почему.** Сайт-словарь посещают, когда уже ищут слово. Рост — в каналах, где ISV *пишут*: Telegram, Discord, браузер, текстовый редактор. Публичный API уже есть, но клиентов к нему нет.

**Что строить (в порядке отдачи).**
- **Telegram-бот** (п.53) — инлайн-поиск, склонение, транслитерация, слово дня; авторизация уже через Telegram. Сообщество ISV живёт в основном там и в Discord.
- **Discord-бот** с теми же командами (корпус на заметную долю состоит из Discord-чатов — значит, аудитория там).
- **Проверка орфографии как словарь Hunspell**: движок умеет породить все формы всех лексем → `.dic/.aff` для LibreOffice, Firefox, любого редактора. Разовая генерация, огромная практическая польза для пишущих на ISV; ни у кого этого нет в таком качестве.
- **Раскладки клавиатуры и мобильная клавиатура с предиктивным вводом** — частотный словарь форм уже посчитан (n-граммы в `corpus.db`).
- **Браузерное расширение** (п.54), но с акцентом не на перевод, а на **транслитерацию страницы на лету** (лат↔кир) и всплывающий разбор ISV-слова.
- **Встраиваемый виджет** «слово + парадигма» для чужих сайтов и блогов.

**Первый шаг.** Hunspell-словарь: это скрипт поверх `generateWordForms`, без новой инфраструктуры, и сразу распространяемый артефакт.

## Направление 7. Устойчивость проекта как институции

Не фича, но без этого остальное хрупко.

- **Лицензирование данных.** Словарь, корпус, переводы, данные RuWordNet/ESSJa/Derksen имеют разные лицензии; для публичного API, LOD (п.71), экспорта (п.65) и академических публикаций нужно явно определить лицензию каждого слоя. Без этого направления 2 и 4 юридически подвешены.
- **Цитируемость**: версионированные релизы данных (DOI через Zenodo), «как цитировать». Превращает сайт в научный источник.
- **Bus factor**: документация для второго разработчика, воспроизводимое развёртывание с нуля (сейчас БД не в git и не восстановимы из скриптов целиком), см. пп. 99–101 обзора.
- **Партнёрства**: официальный комитет ISV / interslavic-dictionary.com — синхронизация словарей в обе стороны вместо параллельного развития; славистические кафедры — верификация и treebank.
- **Финансирование**: гранты на цифровую гуманитаристику (направления 2 и 4 — типичные грантовые темы), пожертвования; хостинг корпуса в 5 ГБ и будущий TTS/MT не бесплатны.

**Рекомендация.** Если выбирать одно стратегическое направление — **учебная платформа (1)**: это самый большой разрыв между заявленным и существующим, она приводит новых людей в язык (а не обслуживает уже пришедших), и движок даёт здесь преимущество, которого нет ни у одного курса. Параллельно, как дешёвые шаги с быстрой отдачей, — **Hunspell-словарь и Telegram-бот (6)** и **режим глоссы в переводчике (3)**. Направление 5 стоит начинать рано, потому что оно разгружает мейнтейнера и является условием для 2.

Чего делать **не** стоит сейчас: обучать собственную MT-модель (п.72) и AI-собеседника (п.73) — мало данных, дорого, а гибрид «LLM + валидация движком» из направления 3 даёт 80% результата без обучения.
